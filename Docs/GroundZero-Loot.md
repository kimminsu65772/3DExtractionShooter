# GroundZero 전리품 연결

WORLD-02(전리품·상호작용)

## 해결한 문제

복원한 맵의 상자 대부분은 외형과 Collider만 남아 있었다. 원본이 사용하는 아이템 체계를 그대로 가져오지 않고, 현재 카탈로그에서 생성 가능한 아이템만 기존 인벤토리 구조에 넣어야 했다.

원본 표를 매번 실행 중 검색하는 대신, 제작 시 원본 확률을 계산해 SO에 저장했다. 런타임에는 SO의 상대 가중치를 추첨하고 아이템 객체를 만들기만 한다. 음식/음료와 미지원 후보를 제외한 뒤 재정규화하므로 원본의 전체 아이템 출현율을 완전히 재현하는 것은 아니다.

2026-10-18 변경: 냄비만 후보로 남은 표는 제외된 원본 확률을 빈 결과로 유지한다. 나머지 혼합 표는 위 재정규화 정책을 유지한다.

## 코드 읽는 순서

1. `Assets/Scripts/Session/SceneBootStrap.cs`: 데이터 준비 후 전리품 초기화를 호출하는 지점.
2. `Assets/Scripts/Loot/StageLootInitializer.cs`: 어떤 상자를 준비하고 언제 결과를 공개하는지.
3. `Assets/Scripts/Loot/LootTable.cs`: 출현 확률/수량/상대 가중치와 후보 선택.
4. `Assets/Scripts/Loot/LootItemFactory.cs`: ID를 실제 카탈로그와 개별 물건으로 바꾸는 부분.
5. `Assets/Scripts/Loot/LootContainer.cs`: 로딩 후 만들어진 내용물을 보관하고 재열기를 처리하는 부분.

## 조정할 설정

SO는 `Assets/GameData/LootTables/GroundZero/`에 있다. 같은 SO를 여러 상자가 공유한다.

- activeChance: 상자 자체가 이번 탐험에 등장할 확률. 실패하면 오브젝트가 비활성화된다.
- minRolls/maxRolls: 아이템을 뽑을 횟수. 중복 추첨을 허용한다.
- emptyRollChance: 추첨 1회가 빈 결과가 될 확률. 빈 결과도 추첨 횟수를 소비하며, 다른 아이템이 나올 때까지 다시 뽑지 않는다. 상자 자체의 activeChance 및 고정 지급 목록과는 별개다.
- entries의 weight: 백분율을 직접 입력하는 필드가 아니라 상대 가중치다. 1과3은 25%와75%다.
- minCount/maxCount: 한 번 뽑혔을 때의 묶음 수량. 탄약은 원본 초기 묶음인 AR/SMG30발, 산탄20발이다.
- inventorySize: 기본 상자 칸 수. 결과가 담기지 않아 물건을 버리지 않도록 실제 필요한 칸을 확보한다. 탄약30발을30칸으로 계산하지는 않는다.
- sourceNote: 원본 태그/레어도 가중치와 출처. 실제 생성 결과나 소모된 내구도를 저장하는 곳이 아니다.

`StageLootInitializer`의 Containers 배열에는 상자170개가 연결되어 있다. 원래 활성 구역88개만 이번 로딩의 대상이며, 시작 상자1개는 기존 고정13항목을 준비한다. 나머지는 무작위 표를 사용한다.

## 주의할 결과

현재 지원 종류로 제한하면 일반 상자·락커·일용품 상자의 후보가 냄비 하나만 남는 경우가 있다. 해당 표에는 원본 기록의 `1 - retainedProbabilityMass`를 emptyRollChance로 넣는다. 예를 들어 Locker_10의 냄비는 추첨당 약 0.845%이며, 나머지는 빈 결과다. 여전히 여러 번 당첨될 수 있지만 매번 냄비가 보장되지는 않는다. 다른 후보가 있는 표, 시작 상자 고정 지급과 상자 배치는 변경하지 않았다. 기존 표를 갱신할 때는 `GroundZeroLootSetup.ApplyEmptyRollPolicy()`를 사용하며, 씬을 삭제·재구성하는 BuildAndApply를 실행할 필요가 없다.

음식/재료/기타 미지원 전용 상자107개는 제거했다. `.codex/backups/2026-10-17-groundzero-loot/`의 씬과 제거 목록으로 되돌릴 수 있다. 남은 상자와 자식 레이어는 Interaction이다.

## 직접 플레이에서 확인

- 로비에서 Stage1로 진입해 전리품 준비 후 로딩이 끝나는지.
- 가까운 상자를 바라보고 F로 열 수 있고, 벽 너머에서는 열리지 않는지.
- 아이템을 가져간 뒤 다시 열어도 채워지지 않는지.
- 다음 탐험에서는 새로운 상자 출현/내용물이 결정되는지.

편집 상태에서 생성/확률/중복 호출/독립 인스턴스와 연결은 검증했다. 실제 플레이는 실행하지 않았다.

상세 규칙과 분석 출처는 `.codex/specs/groundzero-loot-spec.md`에 있다.
