# 인벤토리 UI 연결

관련 기능: INV-01(인벤토리 칸), INV-02(장비), WORLD-02(파밍·상호작용), UI-01(핵심 HUD), ACT-04(탄약·장전).

## 시작

- SampleScene의 PlayerRoot에 InventoryUIController와 PlayerInteractionController를 연결했다. 플레이 시작 시 UI 참조가 없으면 기본 uGUI 화면을 만든다.
- Tab으로 가방을 열고 닫는다. Esc로 닫는다. 1·2는 무기 장비 칸을 선택한다. 키는 InventoryUIController의 Inventory Key에서 바꿀 수 있다.
- LootContainer와 Collider가 있는 물체에 LootInteractable을 추가한다. 가까운 전방에서 F를 누르면 전리품 창이 열린다.
- LootContainer의 Initial Items에 Weapon/Ammo, CSV ID, 수량을 설정한다. 현재 다른 아이템은 지원하지 않는다. 목록이 잘못됐거나 칸이 부족하면 미완성 내용물을 지급하지 않는다. 처음 열 때 한 번 구성하며 다시 열어도 리필하지 않는다.
- 빠른 샘플은 Tools → Inventory → 플레이어 앞 튜토리얼 상자 생성 메뉴로 만든다. 무기 1001과 탄약 2001 90발을 사용하므로 CSV가 다르면 직접 수정한다. 씬은 자동 저장하지 않는다.

## 편집

Tools → Inventory → 현재 씬 UI 준비를 선택하면 기본 화면을 플레이 전에 만든다. Inventory UI 아래 패널 배치, Image, Text를 편집한 뒤 씬을 저장한다. 컨트롤러는 기존 화면 참조가 있으면 다시 생성하지 않는다.

- Slot Template은 숨겨진 공통 칸 원본이다. 아이콘·이름·수량·배경이 분리되어 있다. 실제 가방과 장비 칸은 이 원본을 복사해 만든다.
- InventoryUIController의 Item Visuals에서 ItemType + ItemId를 지정하고 Sprite와 설명을 연결한다. 무기와 탄약에 같은 숫자 ID가 있어도 구분한다.
- 탄약은 인스펙터 아이콘이 없다면 기존 iconAddress를 Sprite로 로드한다. Sprite로 등록된 Addressables 주소여야 한다. 아이콘이 없거나 실패해도 이름과 수량은 표시한다. 같은 주소를 공유하며 UI 종료 시 핸들을 해제한다.
- UIFont를 지정할 수 있다. 기본은 Windows의 Malgun Gothic/Arial이다. 다른 플랫폼 빌드에서는 프로젝트에 포함한 한글 폰트를 연결한다.

## 동작과 책임

무기 장비 칸은 현재 장탄 수만 표시하고 최대 탄창 용량은 생략한다. 하단 무기 퀵슬롯의 장탄 수 / 예비 탄약 표시와 상세 정보의 탄창 용량은 유지한다.

- InventoryUIController: 열기·닫기, 상자 거리 유지, 선택·드래그 요청, 기존 가방/장비 API 호출을 담당한다.
- InventorySlotView: 칸의 그림과 마우스 이벤트만 담당한다. 실제 아이템이나 무기 인스턴스를 새로 만들지 않는다.
- InventoryUILayout: 기본 화면 계층을 만든다. 게임 데이터를 관리하지 않는다.
- InventoryHUDReadModel: 표시 탄약 ID와 같은 ID의 가방 잔탄을 계산한다. 수량을 변경하지 않는다.
- InventoryIconCache: UI 그림 요청을 주소별로 공유하고 자신이 소유한 핸들을 해제한다.
- LootContainer.TryInitializeContents: 처음 열 때 임시 보관함에 전체 목록을 구성하고 모두 성공했을 때만 공개한다. 고정 튜토리얼 목록만 다루며 무작위 전리품 테이블이나 적 사망 드롭은 이번 구현에 포함하지 않는다.

창이 열리면 좌클릭은 빈 공간을 눌러도 발사로 전달하지 않는다. 오른쪽 버튼도 조준 대신 UI 용도로 남긴다. 게임 시간을 멈추지 않고 이동·회피와 적 행동은 유지한다. 열린 창에서 지연 발사 이벤트가 도착해도 발사하지 않는다. 창을 닫을 때 누르고 있던 좌클릭은 떼고 다시 누르기 전까지 발사하지 않는다.

창을 열면 조준점 오브젝트만 숨기고 기본 마우스 커서를 표시하며 화면 제한을 해제한다. 닫으면 열기 전의 커서 표시·제한 상태와 조준점 활성 상태를 복원한다. InventoryUIController는 전환을 요청하고 PlayerAimCursor가 시스템 커서를 변경한다. 플레이어 비활성화 시에는 커서를 다시 숨기지 않는다. 상자에서 멀어지면 상자·가방·상세 정보 창을 함께 닫고 드래그를 취소하며 게임용 커서를 복원한다. 상자를 열지 않고 Tab으로 가방만 연 경우에는 상자 거리 검사를 적용하지 않는다. 새 씬에서는 Aim Cursor와 Crosshair Root를 연결한다. Crosshair Root에는 전체 Canvas가 아니라 조준점 오브젝트를 연결한다.

드래그 시작 때는 실제 아이템을 빼지 않는다. 목적지에 놓을 때 출발 칸이 여전히 같은 객체를 갖고 있는지 확인한 후 이동한다. 잘못된 목적지, 창 닫기, 거리 이탈은 그림만 취소하므로 원래 칸이 유지된다. 장전이 계속 진행될 수 있으므로 드래그 중 수량은 바뀔 수 있다.

전리품 더블클릭은 기존 TryTransferTo로 가능한 만큼 가져온다. 무기는 빈 장비 칸에 먼저 자동 장착한다. 가방과 상자 간 드래그는 지정한 칸에서만 합치기/교환한다. 가방·상자에서 장비 칸으로 드래그할 수 있고 장비에서 가방으로 옮길 수 있다. 장비 간 교환과 장비에서 상자로 직접 이동은 이번 범위 밖이다.

무기 1·2번 HUD는 실제 장비 칸을 참조한다. `45 / 94`는 장탄 수 / 같은 ammoId의 가방 잔탄이다. 다른 등급의 호환 탄약이나 다른 총 안의 탄약은 합산하지 않는다. 마지막 발 소진 후에는 LastLoadedAmmoId로 `0 / 94`를 표시하지만 LoadedAmmoId는 계속 0이므로 기존 빈 탄창 재장전 규칙을 바꾸지 않는다.

한 번도 장전하지 않은 총은 가방에 실제로 보유한 호환 탄약 후보를 먼저 찾는다. 현재 재장전 코드와 같이 보유량이 가장 많은 탄약을 고르고, 동률이면 카탈로그 등록 순서를 따른다. 후보가 있으면 장전 전에도 `0 / 후보 보유량`을 표시하고, 없으면 `0 / 0`을 표시한다. 이 조회는 탄창에 탄약 ID를 기록하거나 탄약을 소비하지 않는다. 이미 장전 이력이 있는 총의 마지막 탄종 표시 정책은 유지한다.

현재 모델에는 모든 경로를 포괄하는 변경 이벤트가 없어 작은 칸 목록의 객체 참조·숫자를 비교한다. 값이 그대로면 텍스트와 이미지를 다시 설정하지 않는다. 반복적인 목록 생성과 문자열 생성은 피하고, 변경된 칸만 다시 그린다. 칸 수가 크게 늘면 모델의 변경 알림으로 전환할 수 있다.

## 아직 연결하지 않은 기능

- 전체 소지 중량·한도·과적 이동 제약. 화면은 미연결 안내와 트랙만 표시한다. 탄약만 더한 값을 전체 무게로 표시하지 않는다.
- 소모품 3~8번 등록·손에 들기·사용. 칸은 미연결 표시이며 저장 공간처럼 사용하지 않는다.
- 근접 V 슬롯, 방어구·헬멧 등 무기 외 장비.
- 탄종 선택 T, 탄창 수동 해제, 버리기, 상자 무작위 추첨, 적 전리품 생성.
- 기존 초기 무기 지급 설정은 변경하지 않았다. 상자만으로 시작하는 최종 튜토리얼은 기존 지급 설정을 별도로 정리한다.

## 검증

자동 검증은 실제 소스를 연결한 .NET 로직 테스트 및 설치된 Unity DLL 기준 컴파일이며 플레이 모드 검증이 아니다. UI 배치와 실제 EventSystem/Physics 입력은 다음 순서로 플레이 모드에서 확인한다.

2026-10-02 검증 결과: 런타임 소스 및 신규 편집 메뉴 컴파일 오류 0개. 인벤토리·탄약 HUD 64/64, 장비 이동·상자 초기화 60/60, 상호작용·UI 입력 차단 21/21 통과. 총 145/145. 테스트 파일은 Assets 밖의 Tests에 두었으며 커밋하지 않았다. Unity 입력·풀·프레임 등 주변 일부는 테스트 대역이다.

1. Tab → 가방 칸 표시 → 빈 공간 좌클릭: 발사 없음. WASD와 회피는 계속 동작한다.
2. 가까운 상자 앞에서 F → 내용물 표시 → 재개방: 내용물 리필 없음.
3. 더블클릭으로 탄약 일부만 수용할 공간을 만든다. 이동한 만큼만 상자에서 감소하고 나머지는 남는다.
4. 드래그로 같은 탄약 합치기, 다른 물건 교환, 잘못된 위치에 놓기: 합계와 원본이 유지된다.
5. 드래그 중 거리 밖으로 이동: 상자·가방·상세 정보 창과 드래그 그림이 닫히고 물건은 원래 칸에 남으며 게임용 커서로 돌아온다. Tab으로 가방만 연 경우에는 이동해도 닫히지 않는다.
6. 무기를 장비에 옮기고 1·2로 선택한다. 장탄 수가 교체·해제 후에도 유지된다.
7. 정확히 같은 탄약 ID만 예비 탄약 HUD에 표시되는지, 마지막 발 후 `0 / 예비량`이 유지되는지 확인한다.
8. 총구 외형 풀 대여를 실패시킨다. 선택한 장비 칸으로 교환 실패 시 양쪽 소유권과 기존 무기는 유지된다.
9. Tab/F로 열 때 조준점이 사라지고 기본 커서가 표시되는지 확인한다. Esc/Tab으로 닫으면 원래 조준점으로 돌아오는지, 열린 상태에서 PlayerRoot를 비활성화해도 기본 커서가 남는지 확인한다.
10. 새 총을 장전하기 전에 호환 탄약을 얻거나 옮긴다. `0 / 보유량`이 즉시 바뀌고, 후보가 없으면 `0 / 0`이 표시되는지 확인한다.

2026-10-02 추가 검증: 미장전 무기의 후보 표시·획득/제거 후 조회·호환성·최대 보유량 및 동률·상태 비변경을 검증하는 테스트 4개를 추가하여 인벤토리·탄약 HUD 테스트 68/68 통과. 이는 .NET 로직 검증이며 Unity 화면에서의 표시 확인은 별도다.
