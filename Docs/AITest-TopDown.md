# AITest: Top-Down BT 실험

관련 기능: ENEMY-02(적 종류 확장)

## 먼저 실행한다

Assets/Scenes/AITest.unity를 열고 Play를 누른다. 파란 캡슐은 WASD로 움직이고 빨간 캡슐은 순찰한다. 게임 화면 좌상단에서 현재 행동과 판단·시야 검사 횟수를 확인한다. 붉은 선은 모의 사격이며 실제 투사체나 피해를 생성하지 않는다. Scene의 기존 카메라와 조명은 보존하고 실험 공간은 Play 시작 시 생성한다.

1. 적의 시야 앞쪽으로 이동하고 순찰 → 추적 → 공격을 관찰한다.
2. 가운데 벽 뒤로 숨고 마지막 발견 위치를 향해 이동하는지 관찰한다.
3. 조사 위치에 도착한 뒤 3초 기다리고 순찰로 돌아가는지 관찰한다.
4. 조사 중 다시 나타나면 기다림을 중단하고 전투를 우선하는지 관찰한다.

NavMesh와 콜라이더의 실제 플레이 동작은 Unity에서 확인해야 한다. 모의 사격 성공은 실제 총기 파이프라인 검증을 뜻하지 않는다. 외부 BT 패키지는 설치하지 않았다. 이번 트리는 조건부 행동을 우선순위로 선택하는 최소 반응형 BT이며 Sequence, 병렬 실행, 에디터 그래프 기능은 아직 없다.

## 위에서 아래로 읽는다

1. AITestSandbox.Start: 실험 공간을 준비하고 대상과 순찰 지점을 연결한다.
2. AITestAgent.Update: 실행과 판단의 주기를 분리한다.
3. AITestAgent.Sense: 볼 수 있는지를 확인하고 발견한 위치를 기억한다.
4. ReactiveSelector.Tick: 공격 → 추적 → 조사 → 순찰 순서로 실행할 후보를 찾는다.
5. EligibleAction: 실행 가능한지 검사하는 조건과 실제 작업을 구분한다.
6. EnemyMotor.TryMoveTo: 선택된 이동을 실행하고 경로 갱신을 제한한다.

쉽게 말하면 Sense는 눈, Selector는 할 일 목록을 고르는 담당자, 행동 노드는 심부름, Motor는 다리다. 눈으로 본 것과 기억 속 위치를 구분해야 벽 뒤의 대상을 초능력처럼 따라가지 않는다.

## 성능 구조와 비용

- 트리와 델리게이트는 Awake에서 한 번 구성한다. 매 판단마다 노드를 만들지 않는다.
- 판단·시야 검사는 기본 0.1초 간격이다. 반응이 최대 한 주기 늦어지는 대신 반복 검사를 줄인다.
- 거리 제곱과 시야각으로 먼저 걸러낸 뒤 필요한 경우에만 Raycast를 수행한다.
- 시야각의 코사인은 설정 변경 시 계산한다.
- 이동은 기존 EnemyMotor의 목적지 변경 임계값과 경로 요청 간격을 재사용한다.
- 회전과 발사 시도는 매 프레임 실행한다. Time.deltaTime 기반 회전을 판단 주기로 호출하면 회전이 느려지기 때문이다.
- 공격 진입 거리와 이탈 거리를 다르게 두어 경계에서 행동이 흔들리는 일을 줄인다.
- HUD 문자열 구성은 관찰용 비용이다. 프로파일링 시 HUD 비용과 AI 판단 비용을 구분한다.
- 다수 적용 중앙 스케줄러, 할당 없는 전체 프레임, 실측 성능 개선은 아직 검증하지 않았다. 이 예제가 최적의 성능을 보장한다는 뜻은 아니다.

## 직접 바꾸고 예측한다

Play 중 생성된 BT 적의 AITestAgent에서 decisionInterval을 0.1에서 0.5로 바꾼다. 행동 반응과 판단 횟수가 어떻게 달라질지 먼저 예상한 뒤 확인한다. Play 중 설정은 종료 시 사라진다.

다음으로 벽 뒤에서 파란 대상의 위치를 계속 바꾼다. 적이 현재 위치와 마지막 발견 위치 중 무엇을 사용하는지 관찰한다. 그 결과를 설명한 뒤 Sense와 Chase를 읽는다.ㄱ

## 남은 검증

- Unity 플레이 모드에서 순찰, 추적, 모의 사격, 시야 차폐, 조사 중단 및 복귀를 확인한다.
- Unity Profiler에서 판단 빈도와 GC Alloc을 측정한다.
- 실제 총기를 시험하려면 AITestAgent의 realAttack에 기존 무기 로드아웃 및 데이터 루트가 준비된 EnemyAttackController를 연결한다. 동일 오브젝트의 EnemyRangedBrain은 함께 실행하지 않는다.
- 기존 EnemyPerception의 청각·피격·조준 제공자와 사망·전리품 연결은 후속 단계에서 통합한다. 현재 예제는 해당 기능을 대체하지 않는다.
